Our position

We built one way to search through iGEM's history, but we know it won't be the best one for long. Technology moves fast, and people will find more efficient ways to search, compare and analyse these projects than we can imagine today. So instead of locking the data behind our interface, we give you the latest version of everything we have - the same files our website runs on. Load it into your own scripts, feed it to an AI, build your own analysis methods, find patterns we never thought to look for.

The knowledge in here belongs to the iGEM teams who wrote their wikis. We only collected it and made it easier to reach. If you build something with it, share it back with the community - that's how iGEM works.

What's inside

All .gz files are gzip-compressed JSON or text - any programming language (or a simple unzip tool) can open them.

records.json.gzThe main file: one entry per project with its full AI summary - problem, approach, summary, key results, failure modes, novelty, references, chassis, techniques, parts, molecules, village, country and the wiki link.
fulltext/text/The full saved wiki text of every project, one file per team and year (e.g. aachen-2014.txt.gz). This is the raw material - the best input for your own AI analysis.
cards.json.gzA short version of every record, used for the result lists.
facets.json.gzThe filter values (year, team section, village, chassis, techniques, parts, molecules, application area, region, country) and which projects have them.
parts.json.gzEvery biological part mentioned in the archive, with iGEM Registry codes where they exist.
index.json.gz, fulltext/index/Our keyword search indexes for the summaries and the wiki texts.
lsa.json.gzThe model behind "Concept + Keyword" search.
meta.json.gz, manifest.jsonCounts, version and checksums.
posts.json, site.json, pages/The blog and the text of this website.

Short field names in records.json.gz:

t, y, uteam name, year, wiki link
p, a, sproblem, approach, summary
kr, fm, n, rfkey results, failure modes, novelty claim, key references
mlthe AI model that wrote the summary
qahow complete the saved wiki text is: GREEN, YELLOW or RED
fthe filter values of that project, including its village (track), region, country and team section

A quick start

In Python, reading every project takes three lines:

import gzip, json
projects = json.load(gzip.open("records.json.gz"))
print(len(projects), projects[0]["t"], projects[0]["y"])

Not a programmer? Unpack the zip, give an AI assistant this page's description and a few of the files, and ask it to write the analysis for you.

Keep in mind

  • The summaries were generated by AI and can contain mistakes. When a detail matters, check it against the wiki text in fulltext/text/ or the original wiki.
  • Some wikis from before 2022 were only partly archived, so their saved text may be incomplete (marked YELLOW or RED in qa).
  • The project content belongs to the respective iGEM teams. Please credit them - and us, if this saved you time.
